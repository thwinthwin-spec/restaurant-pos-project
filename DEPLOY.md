# Deploying Table & Thyme POS (Render)

> Prefer AWS? See [DEPLOY-AWS.md](DEPLOY-AWS.md) for ECS Express Mode + ECR + SSM Parameter Store. AWS App Runner is closed to new customers, so that guide uses ECS Express Mode instead.

The Express server already serves the built React app from `client/dist`, so the whole project deploys as **one Render Web Service**. No separate frontend host, no CORS dance, and no `VITE_API_URL` needed.

## What you need

1. A GitHub account with this repository pushed (already public at `thwinthwin-spec/restaurant-pos-project`).
2. A free [MongoDB Atlas](https://www.mongodb.com/atlas) cluster.
3. A [Render](https://render.com) account connected to that GitHub repo.

No real secrets belong in Git. `server/.env.example` and `client/.env.example` are templates only.

## 1 — MongoDB Atlas

1. Create a free shared cluster and a database user.
2. Under **Network Access**, allow access from anywhere (`0.0.0.0/0`). Render does not publish a fixed egress IP on the free plan.
3. Copy the connection string. It looks like:

   ```text
   mongodb+srv://USERNAME:PASSWORD@cluster.mongodb.net/restaurant_pos?retryWrites=true&w=majority
   ```

Use this as `MONGODB_URI` in Render. Keep it out of the repository.

## 2 — Deploy with the Render Blueprint

`render.yaml` is already in the repo.

1. Render dashboard → **New +** → **Blueprint**.
2. Connect `thwinthwin-spec/restaurant-pos-project`.
3. Render reads `render.yaml` and proposes one service named `table-thyme-pos`.
4. Fill the two `sync: false` values:
   - `MONGODB_URI` — the Atlas string from step 1.
   - `CLIENT_ORIGIN` — use `https://table-thyme-pos.onrender.com` if that name is available; otherwise put the URL Render assigns and redeploy after confirming it.
5. `JWT_SECRET` is generated by Render. Leave it alone.
6. Click **Create resources**. Build command: `npm run install:all && npm run build`. Start command: `npm start`.

Health check: `/api/health` must return `200`.

## 3 — First admin + demo data

On a fresh Atlas database there is no admin yet:

1. Open the deployed URL. You should see **Set up your restaurant**.
2. Create the administrator (for example `owner@restaurant.test` / a strong password), restaurant name and tax rate.
3. To add the 16 demo dishes and 53 sample orders, run the seed script locally with the **same Atlas URI** (never commit it):

   **PowerShell**

   ```powershell
   $env:MONGODB_URI = "mongodb+srv://USERNAME:PASSWORD@cluster.mongodb.net/restaurant_pos?retryWrites=true&w=majority"
   npm run seed
   ```

   **macOS / Linux**

   ```bash
   MONGODB_URI='mongodb+srv://USERNAME:PASSWORD@cluster.mongodb.net/restaurant_pos?retryWrites=true&w=majority' npm run seed
   ```

4. Reload the deployed app. Menu items, orders and reports now have content.

## 4 — Verify

- `https://<your-app>.onrender.com/api/health` → `200`
- Sign in with the admin you created.
- **Point of sale** shows the menu; adding a dish updates the MMK total.
- **Orders** shows the seeded orders; admin confirmation moves totals into **Reports**.
- **Settings** shows your restaurant name and tax rate.

## Notes

- Render free services sleep after inactivity; the first request after a pause takes a few seconds.
- Cookies are `httpOnly`, `Secure`, `SameSite=None` in production (handled by `NODE_ENV=production`), and CSRF protection stays enabled.
- To use a custom domain, add it in Render and set `CLIENT_ORIGIN` to the new HTTPS origin, then redeploy.
- Once the URL is stable, add a **Live demo ↗** link to the matching card in the Portfolio site.
